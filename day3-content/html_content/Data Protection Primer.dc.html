Data protection primer · Azure + Databricks

Encryption and secrets: keeping data unreadable and credentials out of sight

Encryption protects the data. Secrets management protects the credentials that unlock data. Both depend on one principle: the key must never sit next to the lock.

LEARNING OBJECTIVE Describe encryption at rest and in transit, customer-managed keys and secret scope patterns.
01

Why: what goes wrong without them

Why do we need encryption?

Access controls stop people who go through the front door. Encryption protects data when someone gets around them: a copied disk, an intercepted connection, a misplaced backup. Without the key, what they hold is noise.

Why do we need secrets management?

Pipelines connect to databases, APIs and storage with passwords, keys and tokens. A credential typed into code is copied everywhere the code goes, and anyone who reads it can become that pipeline.

03

Customer-managed keys

With a customer-managed key (CMK), the key that protects your data lives in your Azure Key Vault or Managed HSM. You decide who can use it, when it rotates, and you can revoke it. That control comes with the duty to keep it available: lose the key and the data is gone.

Because only the small DEK is wrapped by your key, rotating the CMK re-wraps the DEK. Terabytes of data don't have to be re-encrypted.
Azure Databricks offers CMK for three scopes (Premium plan). Data in your own ADLS account is covered by Azure Storage's own CMK setting.

Secret scopes and Azure Key Vault

A secret scope is a named collection of secrets inside a Databricks workspace. Code asks for a secret by scope + key name; the value is fetched at run time and never written into the notebook. Access to each scope is controlled with ACLs.

THE FLOW
1 · AZURE KEY VAULT Secret is stored Security team adds sql-erp-password to kv-data-prod.
2 · SECRET SCOPE Vault is linked Scope kv-data-prod points at the vault. No secret is copied.
3 · JOB OR NOTEBOOK Fetched at run time The job, running as sp-etl-prod, has READ on the scope and calls dbutils.secrets.get.
4 · OUTPUT Value is redacted If printed, the notebook shows [REDACTED]. Rotate in Key Vault; the next run uses the new value.

Fix: {{ anti.fix }}
Encryption is on by default
At rest and in transit, every zone is encrypted without configuration. CMK changes who holds the key, not whether data is encrypted.
CMK is an operational commitment
Choose it when a regulation or customer requires key control. Then protect, monitor and rotate the key like production infrastructure.
Reference secrets, never paste them
Remove the secret with managed identities where you can. Where you can't, keep it in Key Vault and reference it through a scope.
